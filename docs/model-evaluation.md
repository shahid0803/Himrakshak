# TinyML model evaluation

The checked-in artifact is `himrakshak-synthetic-demo-tree-v2`, a compact
Decision Tree exported for the virtual ESP32 path.

| Item | Result |
|---|---:|
| Dataset | 240,000 synthetic scenario rows |
| Class balance | 80,000 NORMAL / 80,000 WARNING / 80,000 CRITICAL |
| Split | 180,000 train / 60,000 stratified holdout |
| Selected tree | Depth 5, 53 nodes |
| Holdout accuracy | 97.1400% |
| CRITICAL recall | 99.9750% |
| Confusion matrix | `[[19421, 579, 0], [5, 18868, 1127], [0, 5, 19995]]` |

Rows and columns in the matrix are `NORMAL`, `WARNING`, `CRITICAL`.

The 240,000 rows are synthetic samples generated by the repository's own
class-conditioned Monte Carlo script using illustrative feature ranges and
measurement noise. Balanced rejection sampling retains samples only when the
project's explicit threshold rules assign the requested class. They are not
240,000 real sensor readings or landslide observations. The stratified holdout
measures agreement with those synthetic labels only. Increasing the row count
adds generated combinations; it does not establish real-world landslide
prediction accuracy, sensor accuracy, scientific validity, or safety
performance.

The selected tree prioritizes CRITICAL recall. On this synthetic holdout, some
WARNING rows are classified as CRITICAL; this is visible in the confusion
matrix and is a conservative false-positive tradeoff, not evidence of field
performance.

The vibration-burst subtype demonstrates an inspection/anomaly warning over
simulated baseline values; it does not show that an isolated vibration event
predicts slope failure.

The research susceptibility and dynamic early-warning models remain
`NOT_TRAINABLE_DUE_TO_INSUFFICIENT_LABELS`; no real source dataset or event
inventory is bundled as field truth. See [training](tinyml-training.md) and
the [data-source rules](data-sources-and-quality.md).
