# HimRakshak V2 – Virtual ESP32 and TinyML Demonstration

This Wokwi project demonstrates an ESP32 firmware path for an eight-group geotechnical monitoring feature set and a compact 16-feature synthetic TinyML model. It is a virtual software prototype; it does not contain physical sensors or a physical LoRa radio.

## Files to upload to Wokwi

- `sketch.ino`
- `diagram.json`
- `station_config.h`
- `gts_root_r4.h`
- `HimRakshakModel.h`

Copy one station profile from `sender_profiles/` over `station_config.h` before creating each published Wokwi station:

```powershell
Copy-Item sender_profiles\hr01.h station_config.h
# Or use hr02.h / hr03.h for the other station profiles.
```

## Virtual input mapping

| Virtual input | GPIO | Meaning |
|---|---:|---|
| Rainfall potentiometer | 33 | Rainfall-intensity proxy |
| Surface moisture potentiometer | 34 | Surface moisture, % |
| Tilt potentiometer | 35 | Primary tilt-X proxy, degrees |
| Soil-temperature potentiometer | 32 | Temperature proxy, °C |
| Subsurface moisture potentiometer | 36 | Subsurface moisture, % |
| Pore-pressure potentiometer | 39 | Pore-pressure proxy, kPa |
| Vibration pushbutton | 18 | Injects a discrete virtual vibration event |
| Green / Yellow / Red LEDs | 25 / 26 / 27 | Normal / Warning / Critical output |
| Buzzer | 23 | Local alert pattern |

All analog inputs use ESP32 ADC1 pins so they remain compatible with Wi-Fi operation. The battery is currently a fixed demo-health estimate in `station_config.h`, not an ADC-measured battery value.

## Eight environmental groups and proxy disclosure

1. Rainfall: virtual intensity input; 1-hour and 24-hour accumulation use accelerated, seeded demo history (one real second represents one simulated minute).
2. Multi-depth soil moisture: two independent virtual potentiometers.
3. Pore-water pressure: virtual analog potentiometer proxy.
4. Two-axis inclination: tilt-X comes from the potentiometer; tilt-Y is a documented cross-axis proxy.
5. Ground displacement: estimated geometrically from a demonstration lever-arm model applied to tilt; rate is derived from successive samples.
6. Vibration: button-driven RMS/peak/frequency template. This is not a sampled accelerometer waveform or FFT measurement.
7. Soil temperature: analog potentiometer mapping, not a DS18B20.
8. Groundwater: formula-derived proxy from pore pressure and subsurface moisture, not a direct water-level sensor.

The 16 model features and their units/order are defined in `himrakshak/tinyml.py`, `train_tinyml.py`, and the generated C++ model contract. `makeTinyMlFeatures()` must remain in exactly that order.

## TinyML behaviour

`HimRakshakModel.h` is generated by `train_tinyml.py` from the checked-in synthetic demonstration dataset. Firmware runs the compact decision tree locally. Rule-based conditions are fused conservatively: the ML result may raise the demonstration severity, but it cannot lower an existing rule-based WARNING or CRITICAL. Sensor faults and communication status remain separate from environmental assessment.

The synthetic model is a hackathon inference demonstration. Its metrics quantify agreement with generated synthetic scenario labels, not real-world landslide predictive performance.

## Start and observe

1. Start Wokwi and open Serial Monitor at 115200 baud.
2. Confirm the `[TINYML INITIALIZED]` model banner.
3. Adjust each virtual potentiometer and press the vibration button.
4. Inspect the `[GEOTECHNICAL FEATURES]`, `[MOVEMENT FEATURES]`, `[CONTEXT FEATURES]`, `[TINYML INFERENCE]` and `[STATE TRANSITION]` logs.
5. Check the LEDs and buzzer for local response.
6. Try `normal`, `heavy_rain`, and `slope_shift` station profiles.

Network requests use certificate-verified HTTPS and the existing bounded packet queue/retry/sequence reconciliation. HTTP operations still use synchronous Arduino `HTTPClient` requests and can briefly block the main loop; this is a limitation for real-time physical deployment.

## Physical deployment limitations

The current diagram does not include a calibrated rain gauge, geotechnical moisture probes, piezometer, dual-axis inclinometer, extensometer, accelerometer sampling pipeline, DS18B20 probe, or groundwater well transducer. The corresponding features are virtual or derived proxies. The thresholds are illustrative and have not been calibrated by geotechnical professionals. The prototype is not a life-safety device.
